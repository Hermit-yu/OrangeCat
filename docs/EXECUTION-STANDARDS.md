# OrangeCatPanel 项目执行准则

> 版本：v1.0 · 2026-11-14  
> 适用：`/opt/OrangeCatPanel` 全仓库、所有本机/远程节点、代码、数据迁移和部署任务。  
> 权威层级：产品不变量与安全红线以 [`RULES.md`](../RULES.md) 为准；范围、里程碑与功能覆盖以 [`PROJECT-PLAN.md`](PROJECT-PLAN.md) 为准；本文件只管任务如何进入、实现、验证、审查与交付。通用工程方法引用 `software-development/engineering-framework`，不在此重复其细节。

## 1. 执行原则

1. **先事实、后方案**：任务开始时检查代码、测试、Git 状态、运行服务和真实配置；对话记忆、旧计划和“应该如此”不作现状证据。
2. **先完整切片、后扩范围**：按垂直功能推进；每一片贯通真实数据源、Agent/API、UI 操作、失败态和验收。骨架、静态页、假数据、未接线按钮都不是交付。
3. **测试先行**：行为改变先写一条能针对预期行为失败的测试，记录 RED，再做最小实现，记录 GREEN，最后跑相关回归。测试若因语法错误或测试自身异常失败，不算有效 RED。
4. **最小权限、最小变更**：Panel 不执行任意 Shell、不直接访问 Docker Socket；主机操作只能用 Agent 白名单动作与类型化参数。改动不得覆盖或重置他人的未提交文件。
5. **真实状态优先**：主机当前状态以 OS/Docker/Nginx 实际读取为准；写成功后回读验证。DB 缓存、HTTP 200、进程存在、日志里的“成功”单独都不构成业务验收。
6. **每次有回滚点**：写配置/数据/生产二进制前先备份并验证备份可读；失败时回滚到精确版本。严禁整机重启；只用服务级操作。
7. **原生实现，不做源码搬运**：KPanel 仅作为公开能力目录和架构原则参考。严禁复制其代码、目录/内部协议、字段名、UI 文案、图标/图片/品牌素材或测试样例；新的 OrangeCatPanel 数据模型、路由、文案与实现独立设计。许可边界以总计划第 7 节为准。

## 2. 开工门（Definition of Ready）

非琐碎任务开工前，在任务记录或 PR 描述里填写：

- **目标 / 非目标**：一句话说清结果和明确不做的事。
- **允许改动路径**：列出本任务将触碰的目录/文件；未知脏改动不纳入范围。
- **真源 / 基线**：`git rev-parse HEAD`、当前 `git status --short --branch`、相关服务/配置/API 的现场值。
- **风险级别**：按 §3 标 L0–L3。
- **验收契约**：精确测试命令、真实端点/浏览器动作、成功与失败预期。
- **回滚点**：文件备份、数据库快照、旧二进制/镜像或可复现的 Git SHA。
- **权限范围**：本次只读、代码改动、服务重启、线上部署、提交、推送分别授权到哪一步。

目标、路径、真源或可验证性不清楚时，先做只读调查；若有可能改变实现路线的歧义再问用户。不可逆或外部影响操作必须有明确授权。

## 3. 风险级别与门禁

| 级别 | 改动范围 | 最低门禁 |
|---|---|---|
| L0 | 文档、注释、措辞，无行为变化 | diff 检查、Markdown/链接校验 |
| L1 | 单模块可回滚代码，无外部状态变化 | RED→GREEN、相关单测、`bash scripts/check.sh` |
| L2 | 跨层协议、认证、文件/系统写入、数据库迁移 | L1 + 集成测试 + 非法输入/权限/超时/依赖缺失失败注入 + 真实回读 + 回滚演练 |
| L3 | 生产部署、发布、安装升级、公开网络/权限边界变更 | 候选冻结、备份、全套门禁、独立复核、canary、健康检查、可达回滚点、验收记录 |

风险等级跟操作本身走，不因“只是小改”“用户已授权全程”而降低。只有实际跑完该级门禁，才可标记该级已验证。

## 4. 固定工程流程

1. **接单与盘点**：读 `RULES.md`、本计划、相关代码和测试；先执行 `git status`、`git diff --stat`。保留现有脏文件，不用 `git reset`、`git clean`、`checkout --` 或整文件覆盖来清理现场。
2. **任务契约**：记录目标、边界、基线、风险、验收、回滚、权限。
3. **红灯测试**：新增行为测试并运行；确认断言因目标功能缺失而失败。
4. **最小实现**：按一个纵向切片改动，不混入无关重构；所有调用都使用真实 API/Agent 数据源。
5. **本地门禁**：执行 `bash scripts/check.sh`；跨层任务增加集成、并发/失败注入和状态读回。
6. **功能验收**：认证状态下使用真实浏览器走完路径；需要主机写入时用专用测试资源执行后，通过独立 OS 命令回读。
7. **安全与独立复核**：至少检查正确性、信任边界、资源上限、失败恢复、可观测性、证据诚实性。L2/L3 做独立盲审；无可用独立审阅时明确标记“自审，未独立复核”。
8. **更新状态**：同步更新总计划中的能力状态/验收证据；保留原始命令、精确结果与未验证项。
9. **候选交付**：检查 diff、敏感数据、服务依赖、回滚方式；默认不提交、不推送、不部署，除非授权范围包含该动作。

## 5. 功能状态口径

每个能力只能使用下列状态，不得把计划或代码存在当成交付：

- **已验证**：有精确命令与环境记录；真实浏览器显示真实数据/动作；必要写操作回读成功；对应失败路径通过。
- **已实现未实机验证**：代码与自动化测试已通过，但没有目标机/认证浏览器/外部端点证据。
- **未实现**：只有需求、设计、静态 UI、占位 API、空桩或部分依赖链。
- **不适用**：明确写明项目目标、目标主机能力或运行环境为何不适用，不可仅因尚未实现而标此项。

“页面 200”“服务 active”“构建通过”“函数存在”不等于功能可用。按钮需要验证点击后服务端状态改变，并回读真实状态。

## 6. 安全与主机变更规程

- Web 输入不得进入 Shell 字符串、路径拼接或未参数化 SQL；枚举/数值/路径先做格式、范围和授权校验。
- Agent Action 每项都有独立参数 schema、执行时限、输出上限、失败码和审计字段；未注册 action 必须拒绝。
- 反向代理地址头（`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`）默认均不可信；只有来自显式配置的精确可信代理 IP 才能用于来源识别/外部 scheme，且代理配置必须覆盖用户送入的同名头。部署验收时逐项核对代理 IP、UFW 放行源和代理写头行为。
- 浏览器发起的所有已登录状态变更 API 必须同时校验同源 `Origin`（有值时按 scheme/host/port 精确匹配，反代 scheme 来自可信 nginx `X-Forwarded-Proto`）与服务端会话绑定的 CSRF token；前端通过自有 `SameSite=Strict` CSRF cookie 读取 token，并用自定义请求头提交。登录不要求预置 CSRF token；之后新增的任何 POST/PUT/PATCH/DELETE 路由都必须复用同一校验器，不能只保护注销。
- 文件读写先规范化路径、限定允许根、检查符号链接和并发版本；写入走临时文件、校验、`fsync`、原子替换与失败清理。
- 系统配置变更顺序：采集基线 → 展示变更 → 备份 → 写临时配置 → 语法校验 → 原子替换 → 服务级 reload/restart → 回读；失败立即恢复旧配置。
- Docker 删除、卷/镜像清理、终端启动、系统网络和 SSH 变更均以真实影响告知用户；生产环境不拿破坏性操作做验证。
- 凭据只从权限受限的文件/密钥存储/环境注入；永不写 Git、普通日志、审计详情或浏览器截图。API 错误向用户展示经过脱敏的短说明。
- 新功能默认关闭或只读；对外公开页面只返回明确白名单字段，和管理员 API 分开鉴权与缓存。

## 7. 数据、任务与存储

- 当前主机状态实时读，不以历史数据冒充在线值；面板持久化使用 SQLite，按 `RULES.md` 和总计划规定保存审计、用户设置、历史指标、去重状态。
- 每张表有迁移版本、索引/容量边界、保留期；迁移测试至少覆盖新建、存量读取、重启读回、失败回滚。
- JSON 文件只用于有界配置，采用临时文件+原子替换；JSONL 必须轮转；日志、历史、任务并发都需上限。
- 后台任务要能查询状态、阶段、结果、失败原因和有界日志；重试必须幂等；Agent/Panel 重启后的 `running` 状态处理必须有明确规则。

## 8. 前端与接口标准

- 每个视图必须有真实路由、真实 API 请求、字段映射和 DOM 渲染；成功、加载中、无数据、API 失败、权限不足分别处理。
- 前后端字段契约以 Go JSON tag/真实响应为准；变更接口同时更新契约测试和 UI。
- 所有动态主机值都当不可信数据，使用文本插值/DOM textContent 或 HTML 转义；禁止把容器名、站点名、文件名直接拼入未转义 HTML。
- 键盘可用、焦点可见、窄屏可用、状态不只靠颜色表达；正文和控件文字不小于 14px。
- 真实浏览器验证登录、导航、关键交互、错误态及控制台；本机认证访问不可用时必须报告未验证，不用 curl 替代浏览器验收。

## 9. Git、审查与交付

- 当前仓库可能存在任务前遗留的未提交文件。只改本任务范围；提交前逐文件核对 `git diff` 与未跟踪文件，不重置、不覆盖、不擅自清理旧二进制/备份。
- 每个可独立验收的里程碑形成单一候选集；提交/推送需在本任务授权范围内，外部发布需另走 L3 门禁。
- 评审记录至少包含基线 SHA、改动文件、测试命令/结果、真实环境、回滚点、未验证项和许可边界；不得写“应该没问题”。
- 交付回执按“完成 / 验证 / 未完成 / 部署状态 / 回滚点”列出；不把路线图、已写代码或服务存活说成全功能完成。

## 10. 本项目单一门禁入口

运行：`bash scripts/check.sh`

该入口只做本地静态门禁，不部署、不重启服务、不写系统配置。跨层或线上操作仍需按 §3 追加专用验收，不能用本入口替代真实浏览器与主机读回。
