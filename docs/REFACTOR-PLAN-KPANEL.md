# 橘猫面板重构计划（对标 KPanel）

对标参考：
- 源码 https://github.com/kejilion/KPanel （v1.31.0-rc.2，Go 后端 + Vue3 前端，AGPL-3.0-only）
- 官网 https://kpanel.kejilion.sh/
- 在线演示 https://panel.kejilion.pro/overview

> ⚠️ 合规基线（不可逾越）：KPanel 是 **AGPL-3.0-only**。本次重构**只做能力/交互/信息架构层面的概念对标**，
> **绝不复制** KPanel 的任何源码、模板、文案、品牌、图标、主题资源、CSS/组件实现。
> 橘猫面板继续使用 **自有文案（OCP_I18N）+ 自有图标 + 曜石鎏金主题**，代码完全自研。
> 我们当前是 **MIT** 授权，保持不变。

## 一、KPanel 到底强在哪（能力地图）

### 1. 双模式工作台（它最大的差异化）
- **桌面模式**：把监控/终端/文件/AI 做成可拖拽、可最小化/最大化的"窗口"，带任务栏、多窗口并行、
  可选 3D 场景包（霓虹都市/星港轨道）和自定义壁纸。
- **经典模式**：传统侧栏 + 结构化表单 + 高密度信息表，快速巡检。
- **同一套数据、两种壳**：切的是 UI，不是系统。

### 2. 功能覆盖（40+ 视图）
| 领域 | KPanel 视图 |
| --- | --- |
| 概览/监控 | overview, monitoring（历史趋势/体检）, processes |
| 系统中心 | system（主机名/SSH/DNS/时区/Swap/软件源/内核/更新/清理）, settings |
| 网站与 Nginx | sites, sites/monitor, sites/environment（LDNMP） |
| Docker | docker（容器/镜像/网络/卷/日志/性能/更新/备份/迁移/compose） |
| 应用市场 | apps（动态对齐 app.kejilion.sh） |
| 文件 | files（本机+远程）, files/share, gallery |
| 终端 | terminal（多会话/分屏/批处理） |
| 集群 | cluster, cluster/share, terminal/light-nodes |
| AI | ai（多 provider/多模型/多会话） |
| 虚拟机 | virtual-machines |
| 任务/审计 | jobs, audit, activity |
| 通知 | notification-history |
| 多媒体 | music, cinema（媒体库） |
| 其它 | web-browser（内置 Chromium）, offers, diagnostics |

### 3. 架构亮点
- **Agent 模式**：宿主操作由 Unix Socket 上的结构化 Agent 执行（与我们现有 ocp-agent 一致）。
- **权限分层**：Web/API 非特权，PTY 独立授权、有界生命周期。
- **真实主机**：不接管既有环境、不造第二套事实来源（与我们"依赖未就绪不编造"原则一致）。
- **安全**：登录限速、服务端 Session、CSRF、TOTP/Passkey、审计、供应链校验。
- **主题化**：theme/contract.ts 抽象语义色 token；styles/ 多套桌面主题 CSS（win98/xp/scene-pack）。

## 二、我们现有面板对照（家底盘点）

**已有（80+ 路由 / 19 个 section / Go 18k 行 / 单体 index.html 2822 行）**
- 概览、Docker（容器/镜像/网络/卷/日志/统计/compose）、Nginx（站点 CRUD/证书/日志）、
  文件（浏览/读写/上传/回滚/分享）、受控 PTY 终端、进程管理、服务状态、主机体检、
  诊断工具、历史趋势、AI 助手（agnes + 联网）、系统中心、设置（改密/主题/背景/**TOTP**）、
  应用市场（真实 catalog）、集群（本机节点）、定时任务、审计、通知、分享、备份、VM（占位）、
  内置浏览器（有 /api/browser/* 路由）。
- **架构已对齐 KPanel 精髓**：panel + agent + sampler 三进程、Unix socket、Agent 执行宿主操作。

**主要差距**
1. **UI 形态**：我们是**纯经典模式**（侧栏 + 单体 section 切换），无桌面窗口模式。
2. **前端工程**：**单个 2822 行 index.html + 内联 JS**，无组件化、无构建、无路由、无 i18n。
3. **监控**：历史趋势有，但仪表盘卡片、图表交互、体检可视化不如 KPanel 丰富。
4. **集群/多主机**：只有本机节点占位，无多主机接入/远程文件/远程终端。
5. **站点/环境**：Nginx 站点有，但无 LDNMP 环境视图、站点流量监控。
6. **多媒体/应用生态**：无 music/cinema/gallery，应用市场源少。

---

## 三、重构目标

1. **UI 全面升级到"双模式工作台"**——经典模式精修 + 新增桌面窗口模式，整体观感对标 KPanel。
2. **前端组件化**——把单体 HTML 拆成可维护的模块，引入轻量构建，支持 i18n。
3. **功能补齐**——优先补齐"对标 KPanel 且我们有真实数据支撑"的模块（站点环境、监控增强、集群）。
4. **守住底线**——无真实数据源的模块诚实标"依赖未就绪"，绝不造假；安全门禁不放松。

## 四、整体 UI 重构方案（核心）

### 4.1 设计语言（沿用曜石鎏金，升级为设计系统）
- 保留现有 **Obsidian Gold 暖木色** 作为默认主题，但抽成**语义 token 契约**（对齐 KPanel 的
  theme/contract 思路）：`--brand/--surface/--text/--success/--warning/--danger/--border`
  + 间距/圆角/阴影/字号档位，全部走 token，禁止硬编码。
- **新增 2-3 套主题**：曜石鎏金（默认）、暗夜青、极简白；主题即一组 token 覆盖。
- **壁纸系统**：登录页/桌面模式支持内置壁纸 + 用户上传（沿用现有背景上传能力，扩展到桌面）。

### 4.2 双模式外壳（这次重构的最大增量）
- **AppShell（经典模式）**：精修现有侧栏 + 顶栏 + 内容区。
  - 侧栏分组化（像 KPanel）：`概览 / 系统 / 网站 / 容器 / 工具 / 集群 / AI`，
    每组可折叠，带图标（自有 SVG 图标集）。
  - 顶栏：全局搜索（跳模块）、通知铃铛（红点计数）、主题切换、用户菜单、**模式切换开关**。
- **DesktopShell（桌面模式，新增）**：
  - 桌面网格 + 可拖拽窗口（监控/终端/文件/AI/站点 各一个窗口类型）。
  - 任务栏（底部）：运行中窗口图标、开始菜单（列出所有模块）、时钟、系统托盘（CPU/MEM 迷你图）。
  - 窗口能力：拖动/最小化/最大化/关闭/置顶、记住布局到 localStorage。
  - **技术选型**：纯原生 JS/CSS 实现窗口管理（不引 Vue/React 大框架），保持我们
    "单二进制内嵌静态资源、零外部依赖"的部署优势。
- **共享内核**：两种模式复用同一套 API 客户端、同一套组件样式 token、同一登录态。

### 4.3 信息架构（IA 重排）
把 19 个平铺 section 重组成 7 个一级分组：
```
概览   → Overview, 历史趋势
系统   → 系统中心, 设置, 主机体检
网站   → Nginx站点, 站点监控/环境(新增)
容器   → Docker, 应用市场
工具   → 文件, 终端, 进程, 服务, 诊断, 定时任务, 备份, 分享
集群   → 集群, 虚拟机(占位)
AI     → AI助手
```

### 4.4 关键页面 UI 规格（对标 KPanel 经典模式）
- **Overview**：顶部一排指标卡（CPU/MEM/DISK/LOAD/NET），中部实时图表，右侧系统信息 + 快捷入口，
  底部容器/站点摘要。全部卡片走统一 `MetricCard` 样式。
- **监控/历史**：多指标切换 tab + SVG 折线（现有）+ 时间范围 + 体检报告可视化。
- **文件**：双栏（目录树 + 文件表）、面包屑、右键菜单、上传/下载/预览/分享。
- **终端**：多标签 PTY、可选分屏、批量命令。
- **Docker**：容器表格 + 行内操作 + 日志抽屉 + Compose 项目卡。
- **站点**：站点列表 + 配置编辑器 + 证书状态 + 流量小图（新增）。

### 4.5 前端工程化
- 引入 **轻量构建**（Vite + 原生 JS 模块，不用 Vue/React，避免重写和重型依赖），
  输出打包后的静态资源仍由 Go 二进制 embed，保持单文件部署。
- 目录：`web/` 下分 `shell/`（双模式外壳）、`modules/`（各功能面板）、`components/`（MetricCard 等）、
  `theme/`（token + 多主题）、`i18n/`（zh/en）。
- 测试：沿用现有 `index.test.mjs` 门禁思路，扩展到新组件。

## 五、分阶段路线图

**阶段 0：地基（先行）**
- 建立 design token 契约 + 主题系统骨架；搭 Vite 构建；把现有单体 HTML 平滑迁入新结构（不改行为）。

**阶段 1：整体 UI（本次重点）**
- AppShell 经典模式重排（分组侧栏 + 顶栏）+ Design token 全面替换硬编码色。
- Overview 页对标 KPanel 重做。
- 登录页升级（壁纸 + 玻璃拟态卡片，自有实现）。

**阶段 2：桌面模式**
- DesktopShell 窗口管理器 + 任务栏 + 开始菜单 + 至少 4 个窗口（监控/终端/文件/AI）。

**阶段 3：功能补齐（对标 KPanel 高价值模块）**
- 站点环境/LDNMP 视图、站点流量监控、监控体检可视化增强。

**阶段 4：集群/多主机（大）**
- 多主机接入、远程文件、远程终端（依赖现有 cluster 能力扩展）。

> 每阶段独立交付、可运行、过 check.sh 门禁 + 双模型复核 + 手账记账。

## 六、需要哥哥拍板的几个方向问题

1. **UI 优先级**：先做"经典模式精修 + token/主题/Overview"（稳），还是直接上"桌面窗口模式"（炫但工程量大）？
   我建议 **阶段 1（经典精修）先行，桌面模式紧随**。
2. **技术栈**：我倾向 **Vite + 原生 JS 模块**（保持单二进制部署、零框架依赖）。
   若哥哥想上 Vue3（对齐 KPanel 同款生态）也行，但改动和体积更大。
3. **范围**：这次是否包含阶段 3/4 的功能补齐，还是先把 UI 壳做扎实、功能后置？
4. **多媒体（music/cinema/gallery）**：KPanel 有，但我们没有真实数据源，建议**不做**（避免造假）。
