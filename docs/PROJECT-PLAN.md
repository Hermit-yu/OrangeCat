## 1. 产品目标与范围

**目标**：提供单管理员 Linux 运维控制台，从本机开始，可逐步接入多台 Linux 主机；能发现并管理由 SSH、Docker Compose、系统工具或人工创建的真实资源。

**第一运行对象**：当前 OrangeCatPanel 所在 Linux 主机。系统真实状态以 Agent 每次读取结果为准；面板数据库只存面板自有资料，不存一份会冒充当前值的主机影子状态。

**能力目标**：对齐 KPanel 公开展示的完整功能族，并用 OrangeCatPanel 自有设计逐项交付：经典与桌面双工作模式、主机和集群管理、AI 助手、系统/Docker/Nginx/Compose/应用目录、文件/终端、多主机任务与文件互传、网络/硬件体检、网站访问与安全事件分析、通知/只读分享、隔离式内置浏览器、主题/壁纸/3D 场景包、多语言和生态兼容。全量范围见第 3 节及 P0–P15；安全顺序优先，不用占位 UI 冒充功能完成。KPanel 仅作能力参考，不复制其代码、品牌、视觉稿、文案、图片/图标、接口实现或专属场景素材；互通功能须基于公开/获授权接口独立实现并经许可与安全审查。

**非目标**：多租户 SaaS；代替 SSH/Docker/Nginx/systemd；一键重装主机操作系统；替用户自动改动现有公网入口、SSH、防火墙、证书或存量站点；无审计的任意命令执行；未经审批的 AI 写操作。

- 会话仍是进程内状态；重启后全部失效。本地候选已实现有界清理（12 小时 TTL、4096 上限、查询时回收过期、满则淘汰最旧），仍是进程内存态，不声称持久化。

- Agent Unix Socket 父目录 `RuntimeDirectory=ocp` 0750、`LogsDirectory=ocp` 0750、`Group=ocp-agent`、`UMask=0027`；socket 路径存在符号链接/非 socket 时拒绝且不破坏目标，并发连接有上限；不得只靠 `chmod 0660` 宣称边界完整。
- 安装器候选：`installer/install-agent.sh` 与 `installer/install-panel.sh` 默认 `--check` 非变更，`--apply` 需 root、先备份到 `/var/backups/...` 并可回滚；Panel `--apply` 必须显式提供精确可信代理 IP（拒 CIDR/空项），写 `/etc/ocp-panel/trusted-proxy-ips`（0640 root:ocp-panel）。2026-11-14 两个安装器 `--apply` 均已实跑成功；Panel 版安装器随后修补 `enable --now` 不重启缺陷（已 active 时改为 `restart`）。

## 4. 技术架构与不变量

### 4.1 分权结构

```text
浏览器 ── HTTPS / REST / WebSocket ──> ocp-panel（非特权）
                                         │ 结构化 JSON over Unix Socket
                                         ▼
                                  ocp-agent（最小必要主机权限）
                                         ├─ 系统采集/固定系统动作
                                         ├─ Docker Engine API
                                         ├─ Nginx/证书只读发现与校验后变更
                                         └─ 受限文件 broker / 可选 PTY
```

- Agent 是主机能力的唯一执行端；浏览器和 Web API 绝不拼接用户输入到 shell。
- 每个动作有独立 schema、参数边界、超时、输出字节上限、错误类型与审计规则。
- 长任务由独立 worker 执行并持久化状态；HTTP 连接断开不杀掉未知状态的宿主机任务。
- 原子写入、失败恢复与回读真实值是所有写功能共用的事务模式。

### 4.2 数据真源与存储

- 当前 CPU/内存/磁盘/Docker/Nginx/文件状态始终读主机；不拿数据库缓存冒充在线状态。
- SQLite（`modernc.org/sqlite`，CGO-free）存历史指标、审计、可恢复配置、告警去重与任务索引；迁移必须有 schema 版本和回滚/备份测试。
- 终端输出、任务日志、历史采样均必须有容量、保留期和分页/清理策略；不能无界增长。
- Agent 日志与面板审计字段做结构化脱敏；凭据文件权限 `0600`，不进 Git、HTTP 响应、截图或普通日志。

### 4.3 前端与部署

- 保留单二进制/可嵌入前端的目标。经典运维视图优先；Vue 3 + TypeScript + Vite 仅在可构建、数据路由真实、浏览器验收齐全时迁入。
- 不允许仅为追框架新建空壳，不允许用静态卡片代替功能 API。
- 本机现有 systemd 部署和 HTTPS 反代为生产现状；Docker 镜像/一键安装器列为独立分发目标，不在第一波改动中替换当前线上拓扑。

## 5. 里程碑与验收门

所有里程碑顺序执行；每个开发切片先写失败测试，再实现，再跑单测/集成测试。跨进程、鉴权、文件写入及部署为 L2/L3，补失败注入、真机回读和可回滚证据。一个 milestone 可拆多轮，不以日期承诺压过验收。

### P0 — 可信控制面（先于任何写功能）

交付：会话/限速持久化或有界安全替代；按可信代理 IP 解析客户端来源；15 分钟失败窗口实际生效；CSRF + Origin；安全 cookie；密码变更/初始化流程；登录/退出审计；请求大小/JSON 校验；会话过期与登出；Agent socket 权限与并发边界审计；健康端点和统一测试入口。

验收：错误密码 10 次后在 15 分钟窗口结束时解封；反代只采信显式配置的准确 peer IP，未信任来源伪造 `X-Real-IP` 时仍按实际 peer 限流；会话重启语义与文档一致；无 token 的 API 401；跨站 POST 被拒；无效/超长 JSON 被拒；日志和审计中不出现密码；服务端到端登录/退出；线上既有 URL 的真实浏览器测试通过。

### P1 — 本机总览、系统、历史监控与体检

交付：系统/硬件/网络指标补齐；独立采样器和 SQLite schema；图表区间查询与缺数提示；进程管理（先只读后安全结束）；真实服务状态；Ping/TCP/HTTP 和链路诊断；网络/硬件/综合体检任务及有界报告；数据保留任务。

验收：每项指标与 Linux 独立命令对照；测试覆盖容器受限/命令缺失/权限不足/坏输出、私网目标白名单与探测超时；数据库重启读回；30 天/12 月聚合用合成时间数据校验边界；前端登录后实时渲染非空实测值。

状态（2026-11-15 已完成并上线）：全部交付项已实现并通过本地门禁 + 生产实机验收。

- 指标补齐：内存明细/Swap/inode、网卡包数与错误丢包；Agent 10/10 动作探针通过。

## 6. 每个功能的“可用”定义与门禁

一个功能必须同时满足以下全部条件才登记“已验证”：

1. 有实际导航入口和正确的鉴权/权限控制。
2. 有真实 API/Agent 动作；无静态模拟数据、无空实现、无未连接按钮。
3. API 字段来自真实数据源，前后端 shape 一致；错数据/缺权限/依赖不在时明确降级。
4. 功能页面在认证浏览器中真实渲染出数据；交互行为已执行过，而非只 curl 到 200。
5. 有测试（行为变化先有失败测试）、格式/编译/静态检查、集成测试及对应失败场景。
6. 所有写动作在独立测试目标执行过，且回读实际 OS/Docker/Nginx 状态；不拿 production 删除/破坏性动作做验证。
7. 记录候选版本、命令、环境、原始结果、未验证项、回滚点；安全功能再走独立双模型复核。

状态只允许：`已验证` / `已实现未实机验证` / `未实现` / `不适用`。进度矩阵须与实际代码/测试同步，不允许计划写成完成。
