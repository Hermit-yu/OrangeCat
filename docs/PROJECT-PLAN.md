# 橘猫运维面板（OrangeCatPanel）项目计划书

> 版本：v0.1 草案（2026-11-13，智妍）
> 参考标杆：[KPanel](https://github.com/kejilion/KPanel)（AGPL-3.0，只蒸馏思想级架构，**不抄代码、不抄字段名、不抄文档措辞**）
> 定位：单管理员、多台 Linux 主机的运维工作台。从一台机器开始，按需接入更多节点。

---

## 一、技术选型

### 1.1 后端
| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.25+（CGO-free 构建） | 单二进制分发，无运行时依赖，双架构 amd64/arm64 交叉编译简单 |
| HTTP | `net/http` + 路由库（chi 或 std ServeMux） | 面板本体轻量，不引重框架 |
| 持久化 | SQLite（modernc.org/sqlite，纯 Go 驱动） | 只存**面板自有数据**：历史指标、审计记录、用户配置、通知状态；主机真实状态永远实时读取，不落库 |
| Agent 通道 | 本地 Unix Domain Socket + 结构化消息（JSON/protobuf） | 面板 Web/API 非特权运行，宿主机操作全部走 Agent；root PTY 单独授权、有界生命周期 |
| 终端 | 服务端 PTY + WebSocket 转发（xterm.js 前端） | 终端是独立授权的能力，不默认开放 |
| 历史指标 | 双档保留：原始 30 天 + 小时聚合最长 12 个月 | 与业界面板同量级，控制磁盘 |

### 1.2 前端
| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Vue 3 + TypeScript + Vite | 团队已验证工具链；Vite 构建产物可被 Go `embed` 进单二进制 |
| 状态 | Pinia | 轻量、类型友好 |
| 图表 | ECharts（按需引入） | CPU/内存/流量曲线、历史回看 |
| 终端 | xterm.js + 多会话管理 | 多主机会话并排 |
| 界面 | 经典模式为主（侧栏 + 结构化表单 + 高密度信息），桌面模式列为 P2 可选项 | 运维巡检效率优先，花活靠后 |
| 样式 | Tailwind CSS 或纯 CSS token | 不引重 UI 库 |

### 1.3 部署与运行
- **面板本体**：Docker 单镜像多阶段构建（node 构建前端 → go 编译 embed → alpine 运行），`docker compose up` 一条命令起。
- **Agent**：同镜像内以非特权用户跑，或独立小容器挂 `docker.sock` 只读所需能力；节点侧可原生二进制。
- **安装器**：一键脚本只做环境与组件检查、目录创建、服务注册；**不修改**宿主机已有 Nginx、SSH、防火墙、站点。
- **运行基础要求**：systemd（或 OpenRC）+ Docker Engine + Compose v2。

### 1.4 AI（P2，默认关闭）
- OpenAI-compatible 接口（复用现有 agnes-ai.com 端点），多会话。
- 工具集=**固定结构化动作注册表**（查询面板已掌握的状态），写操作默认人工审批，高风险永远审批。
- AI 数据独立存 SQLite，绝不让 AI 会话成为主机状态的第二事实源。

## 二、项目功能（按里程碑切分）

### M0 项目骨架与部署（第 1 周）
- 仓库结构：`panel/`（Web+API）、`agent/`（宿主操作执行器）、`node/`（轻量节点）、`web/`（前端）。
- 安装脚本 + Docker 部署 + 管理员初始化 + 登录（Session、CSRF、限速）。
- **验收**：一台干净容器里 `compose up` 后能登录、面板可访问、审计页可见登录记录。

### M1 系统监控与主机管理（第 2-3 周）
- 首页总览：CPU、内存、磁盘、负载、连接数、网卡流量、公网 IP/ISP、系统时间、服务状态。
- 历史监控：30 天原始 + 12 个月小时聚合；实时进程列表（查看+结束）。
- 主机设置（结构化动作，全部走 Agent 白名单）：主机名、SSH 端口、DNS、时区、Swap、软件源、内核预设（BBR 等）、系统清理。
- **验收**：曲线与 `top`/`df` 实测一致；改主机名/时区走 Agent 成功且审计留痕。

### M2 Docker 与容器管理（第 3-4 周）
- 容器/镜像/网络/卷五区：状态、日志、启停、重启、删除、资源限制查看。
- 容器资源占用曲线；镜像更新检查；卷与网络 CRUD。
- **验收**：面板创建/删除的容器与 `docker ps` 双向一致；日志实时滚动。

### M3 网站与 Nginx（第 5 周）
- **发现优先**：扫描宿主机现有 Nginx vhost 与证书（如 /home/web），只读展示真实配置。
- 建站：静态站、反代站创建（模板化，生成配置 + reload，失败回滚）。
- 证书管理：Let's Encrypt（acme.sh/certbot 二选一接入），到期提醒。
- **验收**：面板能列出宿主机**已存在**的站点与证书且不改它们；新建反代站可访问；证书续期钩子生效。

### M4 文件管理 + 受控终端（第 6 周）
- 文件：浏览/编辑（带行号与校验）/上传/下载/重命名/删除；路径约束（可配置允许根目录）。
- 终端：独立授权开启、会话有界（超时回收）、命令留审计；**不提供任意 shell 的默认开放**。
- **验收**：越权路径（如 /etc/shadow 所在目录）被拒；终端会话超时自动回收且审计可查。

### M5 任务队列 + 通知（第 7 周）
- 后台任务：批量操作、更新检查、体检（IP 解锁/线路/硬件测评）进任务队列，失败可重试。
- 通知渠道（同一时间启用一个）：**Telegram 优先**（复用现有 bot），资源阈值、主机失联/恢复、SSH 登录事件。
- 去重与重试状态原子持久化；停机错过的日期不补发。
- **验收**：SSH 登录事件实测推送到 TG；阈值告警不误报不误重。

### M6 集群与轻量节点（第 8-9 周）
- 轻量节点：无面板主机装一个原生二进制（root 遥测 + 有界 PTY/file broker 分离授权）。
- 中心端：多主机总览（列表/卡片）、历史回看、批量命令、跨主机文件复制。
- 节点接入一次性 token，可撤销；能力按节点版本与授权分级开放。
- **验收**：两台真实主机（本机 + 139）同时在线，面板切主机操作文件/终端正确。

### M7 公开只读分享页（第 10 周）
- 管理员主动开启，生成只读链接：当前运行状态，**不暴露管理入口与 IP 细节**；可随时关闭或重置链接。

### P2 池（不排期，看反馈）
- 桌面模式（窗口化多任务）、应用市场（对齐第三方一键安装清单）、AI 助手（1.4 节）、3D 地球视图。

## 三、项目规则准绳（写代码前逐条对齐，进 CI 检查）

### R1 真实主机是唯一的"事实来源"
面板数据库只存历史指标、审计、用户配置、通知状态；系统/Nginx/Docker/文件的**当前状态永远实时读取**。任何"面板里改好了但主机没变"的状态展示都是 bug。

### R2 来源不限制管理
无论资源是面板、SSH、compose 还是手工创建的，面板都按实际状态发现并继续管理；不强迫导入，不假装是面板创建的。

### R3 权限分层
- Web/API 进程非特权运行，**不直接挂 docker.sock、不挂宿主根目录**。
- 宿主机操作 = 固定动作 + 结构化参数，经 Unix Socket 走 Agent 白名单执行。
- 终端 = 独立授权、有界生命周期、全量审计。面板提供管理员能力 ≠ 把任意 shell 开放给浏览器。

### R4 入口保护
登录限速、服务端 Session、CSRF、可选 TOTP；管理入口默认不暴露公网（只绑内网/网关，经反代 + 证书）。

### R5 变更可恢复
关键配置写入前校验 + 自动备份；失败回滚并明确报告未完成清理项；所有写操作进审计流（谁、何时、做了什么、结果）。

### R6 安装不动存量
安装器不修改既有 Nginx/SSH/防火墙/站点/服务；与存量冲突时提示而非覆盖。

### R7 通知纪律
去重标记先原子持久化再投递；重试有上限；已发送不撤回；停机错过的提醒不补发。

### R8 团队纪律（哥哥立，全部任务通用）
- 高风险/不可逆操作先备份、可回滚；**绝不重启机器**，只允许服务级重启。
- 敏感凭据 0600 落盘加密或环境变量注入，永不进 git、永不进日志。
- 配置卫生：同类配置只留一份权威文件，遗留的先查清再备份后清。
- 交付标准：功能必须实机跑通验证（菜单、CLI、JSON、真实数值），骨架/桩不算交付；成品先自审再交。

### R9 AGPL 学习边界
KPanel 是 AGPL-3.0：本项目**不复制其代码、文件结构、字段命名、文档表述**；只取架构思想（分层 Agent、真实状态优先、审批制 AI）。引用其思想在 LICENSES 中致谢。

### R10 命名与目录
- 项目目录固定 `/opt/OrangeCatPanel/`，代码仓 `github.com/Hermit-yu/OrangeCatPanel`。
- 子模块目录：`panel/ agent/ node/ web/ installer/ docs/`。
- 面板显示名"橘猫运维面板"，二进制 `ocp-panel`，Agent `ocp-agent`。

## 四、目录结构（M0 定稿）

```
/opt/OrangeCatPanel/
├── panel/            # Web+API 单二进制（embed 前端）
│   ├── cmd/ocp-panel/
│   ├── internal/{api,agent-bridge,store,auth,audit}/

│   ├── cmd/ocp-agent/

├── docs/             # 本计划书 + 设计文档
└── docker-compose.yml / Dockerfile
```

## 五、风险与预案
| 风险 | 预案 |
|---|---|
| 面板写操作破坏宿主存量 | 每动作先快照配置/服务状态，失败自动回滚 + 审计报告 |
| Agent 权限过大 | 动作白名单 + 参数 schema 校验 + 默认只读；终端独立开关 |
| 双主机集群协议复杂度膨胀 | M6 先只做"中心轮询 + 单节点操作"，联邦协议后置 |
| 单机 Docker 部署资源占用 | 面板+Agent 合并单容器起步，节点侧二进制 <10MB |
| 与 139/45 已有优化（sysctl/ufw）冲突 | R6 安装不动存量；面板"内核预设"动作只对显式选择的主机生效 |
